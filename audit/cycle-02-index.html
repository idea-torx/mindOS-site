AI agents lose track of their work.
MindOS is the memory they share.

When you run several AI agents, each one only sees its own conversation. MindOS keeps one local record they all read and write: what was decided, what changed since, who is working on what, and what actually proves a job is finished. Everything stays in a single database file on your machine.

The problem

How agent work falls apart, step by step.

Nothing dramatic has to go wrong. A normal Tuesday is enough. Follow one task through an afternoon without a shared memory — then see how the same afternoon looks with one.

Hover not needed — this rail reads top to bottom. Each dot is a moment where a shared record would have changed the outcome.

None of this is a model problem. It is a memory problem. Chat transcripts, scratch files, and Git history each hold a fragment, but none of them can answer the simple questions: who is working on this right now, what changed while we were away, and what proves it is done?

A day with MindOS

One request, from words to finished work.

Here is the same afternoon with MindOS present. It is not another chat window. It is the shared record every agent checks before acting and updates after acting.

  1. 1

    You ask in plain words

    “Fix the render bug on the invoice page.” MindOS records the request as a task anyone can see, with a priority you set or that your lead agent sets.

  2. 2

    An agent claims it, out loud

    Before starting, an agent registers that it owns this task and for how long. If it stops responding, everyone can see the claim expired instead of guessing.

  3. 3

    Work leaves a trail as it happens

    The agent posts short notes while it works. If its session dies halfway through, the next agent reads those notes and continues instead of starting over.

  4. 4

    Finished means proven

    When an agent says it is done, MindOS asks what proves it: test output, a health check, a file hash. The proof is stored as a receipt, and only then does the task close.

  5. 5

    You get an honest answer

    Ask “what happened today?” and MindOS answers from the record: what was decided, what changed, what was completed and what stalled. Not from anyone’s recollection.

Five moments, one line. The spine on the left is the same task — read top to bottom.

What MindOS remembers

The current decision, the old one, and why it changed.

Notes in a file only hold the latest version. Git holds history but no meaning. MindOS keeps each decision with its validity window, so an agent can ask what was true last Tuesday and get a real answer.

Hover the change point — the circle grows to show where one decision replaced the other.

The old decision is never deleted. It is marked superseded, with the reason recorded beside it. That is what lets any agent answer “why are we doing it this way?” without asking you again.

How work stays safe

Every task moves through five states, and only real ones.

Hover or focus each state to see what it protects. The point of the machinery is simple: two agents can never silently work on the same thing, and nothing counts as finished without evidence.

Tab through the states — each one is focusable. The dashed “claim died” node pulses to show recovery is expected, not exceptional.

  • One owner at a time. A claim carries an expiry. If the owner stops responding, the claim lapses instead of blocking everyone.
  • Old owners lose. When a task is re-claimed after a lapse, the new owner gets a higher generation number. Commands from the expired owner are refused automatically.
  • Evidence before closure. The done state is unreachable until a receipt exists. “Tests pass” typed in chat does not count.

The same moment, for real

What the five states look like as actual commands.

No dashboard to babysit. The record is updated by the agents themselves, from the command line. This is a real task moving through its whole life:

mindos — one task, start to finish
$ python3 autopilot.py create --project Trove --title "Ship render fix" --priority P1 task created id=tsk_4f2a priority=P1 project=Trove $ python3 autopilot.py claim tsk_4f2a --owner hermes --minutes 30 lease acquired owner=hermes expires_in=30m lease_epoch=1 $ python3 autopilot.py heartbeat tsk_4f2a --owner hermes --epoch 1 --note "Running verification" heartbeat ok status=running window=15m $ python3 autopilot.py receipt tsk_4f2a --kind verification --payload '{"tests":"pass","health":200}' receipt sealed kind=verification file=0600 sha256=9c1f…e7 $ python3 autopilot.py complete tsk_4f2a --owner hermes --epoch 1 --note "tests pass" task completed evidence=sealed receipt required ✓

In plain words: create says what needs doing, claim says who owns it and until when, heartbeat proves the owner is alive, receipt stores the proof, complete closes it. A completion attempt without a live claim and stored proof is refused.

When things break

A worker disappears. Work continues anyway.

Sessions get killed. Laptops sleep. Networks drop. MindOS assumes this is normal and plans for it rather than treating it as an exception.

The solid branch is MindOS — a new worker continues from the last note. The dashed branch is the guesswork you avoid.

Destructive work rehearses first. Moving records between homes runs against a disposable copy before touching anything real, journals every step, and reverses with one command if the result looks wrong.

The record resists tampering. Every event is chained by hash. If someone edits or deletes history, a verification pass names exactly where the chain breaks.

Why not just…

The tools you already use, honestly compared.

Each of these is good at its job. None of them was built to be the shared operational memory of a fleet of agents. Git stays in charge of your code either way.

The human seam

Where MindOS stops and you decide.

MindOS records and enforces; it does not decide what your agents should want. Certain actions are designed to pause and hold for a person:

  • ⏸
    Holds before irreversible steps. Anything destructive rehearses against a disposable copy first, and applying it for real waits on an explicit go from you.
  • ⏸
    Escalation instead of guessing. When an agent hits ambiguity it cannot resolve from the record, the task parks with a note naming exactly what is unclear.
  • ⏸
    No secrets pass through. Credential-shaped values are blocked or redacted before they can enter any task text, receipt, or archive.

Under the hood

One file you own, four layers above it.

All of this runs on your machine with no server. The whole system is one SQLite database plus Python scripts that read and write it under strict rules.

Tab through the layers — each one lifts on hover/focus. The two dots trace a request going down and evidence coming back up.

What MindOS will not do

A memory and a rulebook. Nothing more.

The pane is focusable — Tab to the shield to hear the boundary read aloud.

Everything lives in one local database file you can open, copy, or delete. Receipts, archives, and databases never leave your machine and never enter any repository. If you delete the home folder, it is gone — there is no cloud copy to chase.

Try it today

Three commands and it exists.

No account, no service, nothing to deploy. If your machine has Python 3.9 or newer, you already have everything else.

git clone <repo-url> mindos
cd mindos
export MINDOS_HOME="$HOME/mindos-home"   # any writable folder works
python3 autopilot.py init
python3 ops.py doctor                        # confirms the new home is healthy

Works today

Task claims with expiry, work notes, proof attached to finished work, decision history with reasons, crash recovery, rehearsed migration, tamper-checked history, and full-text search over all of it.
